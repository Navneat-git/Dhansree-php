# Dhansree (PHP / Laravel)

A Laravel port of the Dhansree e-commerce application, which exists today as a
Node.js monorepo (Next.js 16 + NestJS 11 + Prisma) in the sibling `Dhansree` directory.

> **Status: foundation only.** This repository currently contains the Laravel skeleton, the
> toolchain decisions, and the cross-language cryptography parity layer with its tests. **None of
> the catalogue, checkout, orders, payments, shipping or admin features are ported yet.**
> [docs/MIGRATION_PLAN.md](docs/MIGRATION_PLAN.md) is the plan, including an honest estimate
> (7–9 months full, or 4.5–6 months for a cash-on-delivery-only first cut).

## Why this exists

The Node application is complete and tested (~1,523 passing tests), but its **build** needs
1.19 GiB of memory and three CPU cores, which a 2 GB Lightsail instance cannot provide. The
decision was taken to move to PHP for footprint and maintainability reasons.

The measurement behind that, and the alternative that was considered and declined, are in the Node
repository at `docs/PLATFORM_EVALUATION.md`.

## Requirements

| | |
| --- | --- |
| PHP | **8.3+** (`php8.3` on this machine; the default `php` is 7.4 and will not work) |
| Extensions | pdo_mysql, mbstring, openssl, intl, gd, zip, curl, xml, tokenizer, fileinfo |
| Composer | 2.x |
| MySQL | 8.0.46 (the same version the Node application and its tests use) |
| Node.js | **Not required.** Deliberately. See "Assets" below. |

## Getting started

```bash
composer install
cp .env.example .env
php8.3 artisan key:generate

# 32 random bytes for admin authenticator-seed encryption
php8.3 -r "echo base64_encode(random_bytes(32)), PHP_EOL;"   # -> SECRET_ENCRYPTION_KEY in .env

./scripts/install-tailwind.sh     # one-off: fetches the standalone Tailwind binary
./scripts/build-css.sh --minify

php8.3 artisan serve
```

## Assets

There is **no `package.json`, no Vite and no `node_modules`**, and that is intentional — removing
the Node toolchain is the reason this port exists. CSS is compiled by the
[standalone Tailwind CLI](https://tailwindcss.com/blog/standalone-cli), a single binary:

```bash
./scripts/build-css.sh            # once
./scripts/build-css.sh --watch    # while developing
./scripts/build-css.sh --minify   # for production
```

Tailwind 4.3.3 — the same version the Node application uses, so the existing design tokens in its
`globals.css` port across directly. The binary is 107 MB and is **not committed**; fetch it with
`scripts/install-tailwind.sh`.

Interactivity is Livewire 3 (admin panel) and Alpine.js (storefront), neither of which needs a
build step.

## Cryptography parity — read this before touching authentication

`app/Support/Crypto/` and `app/Support/Razorpay/` are ports of the Node implementations, and they
are **wire-compatible on purpose**. This was verified, not assumed:

| What | Result |
| --- | --- |
| Admin passwords (Argon2id `m=19456,t=2,p=1`) | PHP's `password_verify()` reads the existing hashes → **no password resets** |
| Admin TOTP seeds (AES-256-GCM, `v1.<keyid>.<iv>.<tag>.<ct>`, AAD-bound to the row) | PHP decrypts the existing rows → **no re-enrolment** |
| TOTP codes (SHA-1 / 6 digits / 30 s / ±1 step) | 21/21 codes identical to the Node implementation |
| Razorpay checkout and webhook signatures | Identical digests |

`tests/Fixtures/node-parity.json` is generated by the **Node application's own compiled modules**,
not by a re-description of them:

```bash
./scripts/regenerate-parity-fixtures.sh    # needs the Node app built (npm run build there)
php8.3 vendor/bin/phpunit tests/Unit/Crypto/NodeParityTest.php
```

**If a parity test fails, fix the PHP port — never the fixture.** A fixture edited to make a test
pass is how administrators get locked out of production.

## Testing

```bash
php8.3 vendor/bin/phpunit
```

The Node application's **175 Playwright browser tests** are the parity harness for the port as a
whole (see MIGRATION_PLAN.md section 6). They drive a real browser and do not care what language
serves the pages, so they can validate this application once it serves routes.

## Relationship to the Node application

The Node application in `../Dhansree` is **not modified by this work** and remains runnable. It is
the reference implementation: when this port and that one disagree, that one is right until a
deliberate decision says otherwise.
